## 第 2 轮 · agent（只读检查）

先查两个只读接口，没有改任何东西。

```
GET /api/memory-shield/state
{"ok":true,"data":{"layer":"profile","presetName":"","enabled":false,
 "hintDismissed":false,"showInSettings":true}}

GET /api/memory-shield/health
{"ok":true,"version":"0.1.8","layer":"profile","enabled":false,
 "presetName":"default","shadowTools":0,"shadowSections":0}
```

现状：

- 装在这一层：**profile 层**（`layer: "profile"`）。意思是插件本身已装进 web profile，但按设计，profile 层只提供状态接口和提示，不真正遮蔽任何东西。
- 有没有启用：**没有**（`enabled: false`；实际生效的遮蔽工具 0 个、区块 0 个）。
- 挂在哪个 preset：**没挂**。这里有个口径要注意——`/health` 的 `presetName` 是配置里的默认值 `"default"`，不代表真的挂到了名叫 default 的 preset；`/state` 的 `presetName` 为空串，才是它的真实挂载状态。两者不一致是这个版本的一个小毛病（见文末「模拟发现的问题」第 1 条）。

也就是说：**它现在是「装着但没启用」，要让遮蔽生效，得把它挂到某个 preset 的插件列表里。**

## 第 3 轮 · agent（说明改法，仍不动手）

要改的文件只有一个：

```
<DSH_HOME>\profiles\web\cordis.patch.yml
```
（`<DSH_HOME>` 指你的 DSH 家目录，例如 `%USERPROFILE%\.dsh`；写这段示例时用的是作者机器上的路径）

这个文件里已经有现成的 `preset-standard`（第 331 行起），它的 `plugins:` 列表从第 337 行开始，第一项是 `- id: persona`。要在**这个列表里**插一项，缩进对齐同级的 `- id: agent-instructions`：

```yaml
      - id: memory-shield
        name: dsh-memory-shield
        config:
          enabled: true
```

插在 `- id: agent-instructions` 之前或之后都可以（顺序不影响遮蔽，只影响加载先后）。**不要**另起一个 `- id: preset-standard` 块——preset 的 `config` 是整体替换，只带 `plugins` 的新块会把 standard 原有的 30 多个插件全部清掉。

也**不要**改 `dsh.profile.bundles`，不要在 profile 层把 `enabled` 设成 true：那样会和全局记忆插件撞名，报 `prompt context "memory:snapshot" is already registered`。

改完的影响：

- 只有 **standard 这个 preset 下的会话**看不到记忆（记忆数据不删，只是不注入）；
- 其他 preset（比如专门给某个通道用的那个）照旧；
- 消息级注入（pre-step 往用户消息里塞的内容）挡不住，这是内核位置决定的；
- 要**重启 DSH 并新建一个 standard preset 的会话**才生效，老会话按启动时的 preset 跑，不会变。

遮蔽名单用默认的就行（内置已覆盖常见记忆插件：memory-evolve、memory-evolve 的几个 section、memoir、dtodo 等）。你现在没装名单外的记忆插件，所以不问你。

要我现在改吗？改之前我会把 `cordis.patch.yml` 备份到同目录（文件名加 `.bak` 和时间戳），只动这一处。

## 模拟发现的问题

1. **`/health` 的 `presetName` 在 profile 层给了假值 `"default"`**。它读的是配置里的默认值，不是真实挂载（`/state` 同字段给的是空串）。提示词让 agent「presetName 看 /health」，agent 就会误报「已挂在 default preset」。修法：`index.js` 的 health handler 改成和 state 一致——`presetName: inst?.layer === 'preset' ? (cfg.presetName || 'default') : ''`。
2. **提示词没说「profile 层 + enabled=false 就是未启用」这个判读口径**。agent 看到 `layer: profile` 可能以为「还得先把它从 profile 层挪走」，多绕一轮。可在提示词里补一句「如果 layer 是 profile 且 enabled false，说明只是装着没启用，直接进第二步」。
3. **提示词没让 agent 先确认目标 preset 存在**。本机 `preset-standard` 在文件里，但如果用户用的是自定义 preset 名，agent 可能瞎猜一个不存在的 id。补一句「先在这个文件里找到你要挂的那个 preset，确认它存在再插」。
4. 一个好消息：`/cache` 之外的路径都按预期返回了 JSON，没有 404、没有跨域问题，agent 不需要额外兜底。
